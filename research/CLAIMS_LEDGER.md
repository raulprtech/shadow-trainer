## Rules

The v6 bounded-surface evaluator and supervisor passed 24 offline tests and a
one-case physical development equivalence/reuse gate. The final v6 session then
completed B0/A/B with 6/6 cases each. Its post-run audit rechecked source,
checkpoint, code, summary and prediction hashes, 18 receipts, cohort order and
resource limits. Earlier incomplete attempts remain diagnostic, never timing
baselines. Historical textual audit shows the six-case final cohort was already
evaluated in r1, so r2 is a same-cohort exploratory replication, not a new
independent validation. All 18 HD95 values are explicitly unavailable by the
20-million-voxel memory rule; cyst Dice was zero, including four positive cases.

STU-Net development evidence update: `research/evidence/stunet-development-audit-20260921-r1/mask-audit.json`
verifies all 24 saved development predictions against current reference masks,
including count equality and image/reference/prediction geometry. This strengthens
metric correctness only; it does not establish historical checkpoint provenance,
held-out generalization or clinical validity. Prospective receipt checks have
17 passing CPU checks (10 unit tests and 7 integrated synthetic evaluator
scenarios), recorded in `research/evidence/stunet-development-audit-20260921-r1/evaluator-cpu-acceptance.json`.
The real evaluator uses an injected tiny CPU model in these scenarios; this
does not itself validate STU-Net. The separate physical development acceptance
is limited to one B0 case and the v6 reader, not final-cohort efficacy.

1. Product and application materials may use only the “Allowed wording” column.

3. Diagnostic and invalid runs may explain engineering decisions, never support
   performance numbers.
4. Any changed source artifact changes the evidence-bundle SHA-256 and requires
   review before figures or manuscript tables are regenerated.
